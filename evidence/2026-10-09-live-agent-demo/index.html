Can an AI agent get a working database from Neon, with no human?

Yes. On Friday 9 Oct 2026 (10:08–10:10 pm Sydney time) an AI agent went from just the name “Neon” to a working database with real records in it. A separate checker confirmed the result, and three tests built to fail all failed.

Result: independent check PASS · 3 of 3 must-fail tests FAIL as expected
Cost A$0 · no sign-up · no card · no person involved

Who the agent was (please read)

The agent was Miles Mercer’s own live AI session, logged step by step as it ran. It was not a separate AI product running unattended. It chose each step during the run, using the public Neon pages it fetched. The AI behind it already knows some public facts about Neon, so the log lists which pages it actually read. This differs from our earlier scripted Neon sample of 6 Oct.

What the agent did

  1. Found the way in (10:08 pm). It read Neon’s public guide for AI agents (neon.com/llms.txt). That guide points agents with no account to a no-sign-up “claimable” database (neon.com/auth.md).
  2. Got access (10:08 pm). Neon gave it a new database straight away. Neon removes it after 72 hours unless someone claims it.
  3. Hit a snag and worked around it (10:09 pm). Our machine’s network blocked the usual database connection. The agent went back to Neon’s docs and switched to Neon’s web-based connection.
  4. Did the work (10:10 pm). It created an orders table, added 5 records we had written down in advance, and ran a summary: 3 pilots worth A$13,500 and 2 implementations worth A$75,000.

How we checked it (not the agent’s word for it)

A separate checking program, sharing no code with the agent, got its own fresh login from Neon, read the table and compared a fingerprint of the records with the list written down before the work started.

  • Agent’s database: PASS (10:10:13 pm). All 5 records and the summary matched. Fingerprint 6373f1e4…e89e8d.
  • Wrong password: FAIL (10:10:21 pm). The login was refused.
  • A brand-new empty Neon database: FAIL (10:10:28 pm). The table wasn’t there.
  • A look-alike table with one amount changed (A$4,000 instead of A$4,500): FAIL (10:10:41 pm). The fingerprint didn’t match.

The three failures show the checker doesn’t just approve whatever it’s pointed at.
